# 04 — Desktop UI: the Tauri app shell and Assist mode

React 19 + TypeScript + Vite in the Tauri 2.11 webview (A15). The UI holds **no secrets and no logic**: it renders state pushed from Rust and sends commands. This doc owns the **Tauri desktop** front end — the shell (windows, panels, tray, listening bar, status strip, conversation strip, onboarding, Settings, the Rust↔TS protocol) and **Assist** mode. The **terminal** front end is owned by `plans/14-tui.md`: `neo-tui` behind `neo tui`. Both are thin front ends over one core (P12) — each renders state pushed from the same `Runtime` facade and sends typed commands back, and neither holds a secret or makes a decision. Doc 11 owns everything inside the Hypercanvas; this doc only defines how **Design** mode plugs into the shell.

## 1. Design goals

At a glance, from across the room, the user can answer four questions:

| # | Question | Answered by |
|---|---|---|
| 1 | **Is it listening?** | listening bar · tray icon · pill dot — one `ListenState`, and it always agrees with macOS's orange mic dot |
| 2 | **What did it hear or read?** | Conversation thread: every utterance and typed message, with its intake tag |
| 3 | **What is it thinking?** | Mind pane: Route, Thought, Steer ticker, Judgment — the real numbers from Jev |
| 4 | **What is it doing?** | Queue card + pill step sentence + target ring + managed-Chrome presence chip |

Non-goals: no chat-app look (voice is primary, the composer is slim, P4); no hidden state (doubt, denial and spend are always visible); no setting that can loosen safety from outside Settings → Safety.

## 2. Visual language

Dark, glassy, restrained. **One accent per state; motion only where it carries state.** No light theme in v1.

- **Type**: system fonts only, zero webfont bytes — `system-ui` (SF Pro) for everything, `ui-monospace` (SF Mono) for element indices, probabilities, model ids, JSON. Scale (px): 11 caption · 12 meta · 13 body · 15 emphasis · 18 title · 24 bar label. Weights 400/500/600. Tabular numerals for every number that updates.
- **Spacing scale** (px): 2 · 4 · 8 · 12 · 16 · 24 · 32 · 48. **Radius**: 6 chip · 10 card · 16 panel · 999 pill. Hairline borders, no drop shadows inside `main`; panels get one soft shadow.
- **Glass**: `backdrop-filter: blur(24px) saturate(1.2)` over `--surface`; honours macOS *Reduce transparency* by switching to opaque `--surface-solid`.
- **Motion**: 120 ms micro, 200 ms state change, 320 ms pane/mode change; ease-out only. Continuous motion exists in exactly three places: the waveform, the running card's pulse, the TRANSCRIBING shimmer.

| Token | Value | Role |
|---|---|---|
| `--bg` | `#0B0D10` | window base |
| `--surface` / `--surface-solid` | `rgba(255,255,255,.06)` / `#14171C` | cards, bar, panels |
| `--surface-raised` | `rgba(255,255,255,.10)` | hover, selected, popovers |
| `--border` | `rgba(255,255,255,.10)` | hairlines |
| `--text` / `--text-2` / `--text-3` | `#ECEEF2` / `#A4ABB8` / `#6F7785` | primary / secondary (≥ 4.5:1) / decorative only, never the sole carrier of information |
| `--listen` | `#35D0BA` | LISTENING, Listen toggle on |
| `--hearing` | `#6FF2DE` | HEARING YOU, TRANSCRIBING |
| `--speaking` | `#A78BFA` | SPEAKING, bot-voice glyph |
| `--working` | `#5AA9FF` | running task, Steer ticker, target ring, Chrome presence |
| `--confirm` | `#F5B544` | confirm cards, `enqueue?` chips, below-threshold bars, paused |
| `--danger` | `#F26D6D` | MIC LOST, NO PERMISSION, denied, failed, kill switch |
| `--ok` | `#5BD68A` | done, healthy, approved |
| `--muted` | `#6F7785` | MUTED, ignored chips, cancelled |

**Accessibility** (acceptance criteria, not aspirations): text contrast ≥ 4.5:1, UI glyphs ≥ 3:1; state is never colour alone — every state has a label and a glyph; `prefers-reduced-motion` → waveform becomes a level bar stepped at 4 Hz, shimmer becomes the static word "Transcribing…", pulses become solid borders, pane transitions cut; every control has a VoiceOver label (`aria-label` names the state: "Listening. Press to stop listening"); bot turns are an `aria-live="polite"` region, confirm and ask cards `assertive`; full keyboard operation with a visible 2 px focus ring, roving tabindex inside lists, no hover-only affordance; hit targets ≥ 28 px.

## 3. Windows and panels

| Surface | Kind | Purpose | Lifecycle | Focus |
|---|---|---|---|---|
| `main` | normal Tauri window, min 720×520, size/position remembered | Assist / Design modes, Settings, onboarding | created at launch; close = hide (app keeps running); tray or `⌥⌘S` shows it | normal key window |
| `design` | second normal window loading the `main` entry with `?mode=design` | Design mode popped out (§4) | created on pop-out, destroyed on pop-in or close | normal key window |
| `pill` | **NSPanel** via `tauri-nspanel` pinned to revision `c9ec2130422200f0863b23dfdad02b133a529b07`: passive subclass with `canBecomeKeyWindow = false`, borderless `nonactivatingPanel`, level `PopUpMenu`, `fullScreenAuxiliary`, `canJoinAllSpaces`, `stationary`, `ignoresCycle`, `hidesOnDeactivate(false)` | capsule: state dot · mini waveform · current step sentence · Stop. Expands for a pending confirm (action sentence + Approve / Deny, mouse only) and for a quick-entry result | visible whenever `main` is hidden **and** the bot is listening, working or waiting on the user; setting can force always/never | **never** key; receives mouse clicks without activating Stark or stealing target-app focus |
| `ring` | one transparent passive NSPanel per display, level `Status`, same passive subclass/Space flags as `pill`, sized to the display frame, `ignoresMouseEvents = true` | draws the target ring (`--working`, 150 ms) around the element about to be acted on | created at launch, rebuilt on display-configuration change; idle = empty and transparent | never key; a real HID click passes through to the target app |
| `quick-entry` | separate key-capable NSPanel subclass, borderless `nonactivatingPanel`, level `PopUpMenu`, same Space flags | Spotlight-style one-line composer (`⌥⌘Space`) | created lazily; open switches `Prohibited → Accessory`, makes the panel key and focuses the field; hidden on `Esc`, send, or focus loss; close restores the prior app then returns to `Prohibited` | key only while open; never opens or activates `main` |
| tray | `TrayIconBuilder`, **template icons** (one glyph per `ListenState`, plus a badge dot when a card needs the user) | menu: Listen on/off · Pause queue · Stop current task · Show Stark's Chrome · Show window · Settings… · Quit | app lifetime | — |

Rules:

- `app.macOSPrivateApi: true` is required for transparent windows (acceptable — never the Mac App Store, P1).
- Panels exist because a plain always-on-top window **cannot sit above a fullscreen app's Space**. Passive panels must never become key: stealing focus from the target app breaks automation.
- **Activation policy**: `Regular` while `main` or `design` is visible; `Accessory` only while quick entry owns key focus; `Prohibited` while only passive/background surfaces remain. The S6 spike proved all three runtime transitions. Changing policy may order panels out, so the controller reapplies desired visibility after every transition rather than assuming AppKit preserves it.
- **Architecture seam**: `src-tauri::panels::PanelController` is the sole owner of panel builders, subclasses, activation policy, AppKit main-thread calls, previous-app focus restoration, per-display geometry, and visibility reconciliation. Its public operations are `set_normal_window_visible`, `show_passive`, `hide_passive`, `open_quick_entry`, `close_quick_entry`, and `reconfigure_displays`; commands/events carry product state, not AppKit handles. No crate below `src-tauri` depends on Tauri or `tauri-nspanel`.
- **Multi-display + Spaces**: `main` lives in one Space like any window. `pill` remembers its position per display-configuration hash; if its display disappears it moves to the main display's top-right under the menu bar. `quick-entry` opens on the display holding the cursor, centred in the upper third. `ring` geometry: observers hand Rust a rect in global points (top-left origin); **one Rust function** maps it to the owning display's panel coordinates with the scale factor applied. A target spanning two displays is ringed on the display holding its centre.
- **Own windows are excluded from automation**: `AxObserver` drops every element whose pid is ours; the navigator never targets them; the managed Chrome profile cannot open `tauri://` origins. Because the navigator hit-tests click occlusion, **the pill dodges**: if the target rect intersects the pill, Rust moves the pill to the nearest free corner before the action and back after the task.
- **No Screen Recording seam**: panel regression captures use each owned `WKWebView`'s native snapshot API. Never use `screencapture`, desktop/window capture APIs, or a screenshot fallback for panel verification (P10).
- `single-instance`: a second launch shows `main` of the first.

## 4. Modes: Assist and Design

`main` has two modes (A15). They share three shell components, mounted once above the mode router so they never remount on a switch:

| Shared | Assist | Design |
|---|---|---|
| **listening bar** (top, 56 px, never scrolls) | same | same |
| **status strip** (bottom, 24 px) | same | same, plus doc 11's zoom/selection readout on the left |
| **conversation strip** (`ConversationThread` + `Composer`) | rendered full-height as the **Conversation** pane | rendered as the docked strip under the canvas: last 3 turns, composer, current agent pass + Steer ticker; drag up to expand to a half-height thread |

```
Assist                                                   Design (canvas internals: doc 11)
┌───────────────── listening bar ─────────────────┐     ┌──────────── listening bar ────────────┐
│ Conversation  │ Queue          │ Mind           │     │ layers/tokens │ HYPERCANVAS │ inspector│
│ thread        │ task cards     │ TraceTimeline  │     │ takes shelf   │             │          │
│ ─ composer ─  │                │                │     ├───────────────┴─────────────┴──────────┤
├───────────────┴────────────────┴────────────────┤     │ conversation strip · pass · Steer      │
│ status strip                                    │     ├────────────────────────────────────────┤
└─────────────────────────────────────────────────┘     │ status strip                           │
                                                          └────────────────────────────────────────┘
```

- Assist columns are resizable (defaults 32 / 30 / 38 %); under 900 px they collapse to tabs (Conversation · Queue · Mind) with a badge on any tab holding a card that needs the user.
- **Switching**: mode toggle at the left of the listening bar (`Assist | Design`), `⌘⇧A` / `⌘⇧D`, the command palette, or by voice. The app switches by itself in exactly one case: a task routed `design` starts and `main` is visible → Design opens (setting `follow_design_tasks`, default on). It never switches away from a mode the user is typing in. Queue and Mind stay reachable in Design as a right-edge drawer (`⌘2` / `⌘3`), so a confirm card is never more than one keystroke away; a pending confirm or ask also renders inline in the conversation strip.
- **Pop-out**: "Open canvas in its own window" creates the `design` window (same Vite entry, same store code, its own bar/strip instances fed by the same events); `main` returns to Assist. Closing `design` pops it back in.
- With the `neo-media` pack disabled, Design mode shows the **Enable media** card (doc 07 flow) plus the pack-free parts of the canvas doc 11 allows.
- Context sent with every utterance/message: `mode`, and in Design the selection + viewport (doc 11).

## 5. Listening bar

One source — `ListenState` from Rust — drives four surfaces: bar, tray icon, pill dot, quick-entry glyph.

| State | Trigger | Look |
|---|---|---|
| `LISTENING` | stream open, VAD idle | `--listen`; waveform breathing with the real mic level; label "Listening" |
| `HEARING YOU` | VAD speech start (local, instant, before any network) | `--hearing`; full-amplitude waveform; "Hearing you…"; live partial text when streaming STT is on |
| `TRANSCRIBING` | utterance closed → transcript returned | `--hearing` shimmer sweep; "Transcribing…"; returns to LISTENING (capture continues underneath) |
| `SPEAKING` | TTS playing (+ 200 ms tail) | `--speaking`; waveform driven by TTS output level; "Speaking" + "mic gated" tag in half-duplex |
| `MUTED` | Listen off (toggle, hotkey, tray, voice "stop listening") | flat `--muted` line, struck mic, "Not listening" |
| `PAUSED: SCREEN LOCKED` | screen locked / display asleep (P7) | flat `--confirm` line, lock glyph; on unlock returns to the previous state by itself |
| `MIC LOST` | device disconnected / default device changed and rebuild failed | `--danger`; "Microphone lost"; button **Choose microphone** |
| `NO PERMISSION` | TCC denied or revoked | `--danger`; "No microphone access"; button **Open System Settings** → onboarding re-entry (§11) |

- Bar contents, left→right: mode toggle · state glyph + label · waveform (flex) · input-device name · the **Listen toggle** (largest control in the app) · kill switch.
- **Honesty rule**: macOS's orange mic dot is on exactly when the bar says LISTENING / HEARING YOU / TRANSCRIBING / SPEAKING-in-full-duplex, and off in MUTED, PAUSED, MIC LOST, NO PERMISSION — because `neo-voice` **drops the capture stream** in those states rather than ignoring it. Manual check in every release: toggle, lock, unplug → the dot follows within 1 s.
- First launch starts **on** (P5), straight after the onboarding statement; afterwards the last state is restored. With Listen off, typing still works.
- Push-to-talk mode replaces LISTENING with `MUTED` + "Hold ⌥Space to talk"; name-required mode adds "say 'Stark…'" under the label.

## 6. Assist · Conversation

One thread for every **message** — voice, typed, bot (P4). Voice-first: the thread fills with what was *heard*; the composer is a slim single line at the bottom, placeholder *"…or type"*.

**User turns** — bubble + source glyph (`mic` heard · `keyboard` typed · `bolt` quick-entry) + an **intake tag**:

| Tag | Meaning | Look / action |
|---|---|---|
| `→ task · navigate` (or `design` · `media` · `multi` · `routine:<name>`) | `new_task` with its **route** | links to the Queue card |
| `→ amend` · `→ answer` · `→ cancel` · `→ question` | other intents | links to the task / question it landed on |
| `ignored 0.12` | `chatter` (voice only) or dropped by the pre-intake filter | greyed; click → **force-enqueue** (logged for calibration) |
| `enqueue? 0.55` | `P(new_task)` between the ask and enqueue thresholds, or Jev intake unreachable | `--confirm`; click, `↩`, or say "yes" → enqueue; expires after 60 s to `ignored` |

Hover/focus on any tag shows the full intent and route probability split. Typed messages never show `ignored` (the `chatter` option is dropped for typed input) and get no extra trust downstream.

**Bot turns**: task result (`finish` summary, linked to its trace) · direct answer to a `question` (streamed) · **question** from `ask_user` with **quick-reply chips** (the options) and the composer retargeted to "Answer…" — answered **in-thread** by chip, typing, or the next utterance; the Queue's ask card mirrors it and either resolves both · confirm request (compact mirror of the confirm card, same buttons) · media results as take thumbnails (click → the take on the canvas) · enablement offers ("Media tools are off. Enable?") · notices (Jev outage, cap reached). When TTS is on, the spoken sentence is the first sentence of the bubble, marked with the `--speaking` glyph — one text for eye and ear.

**Composer**: one line growing to 5; `↩` send, `⇧↩` newline, `↑` edits the last typed message while its task is still `queued`; paste/drop **attachments** (images, files) → `AttachmentChip`s, staged by Rust into the task (images reach Sol's vision and `media_import` when the pack is on); max 10 files, 25 MB each; the webview passes paths/bytes to Rust and never reads files back. Secrets are never accepted here — a pasted string matching a key pattern is refused with a pointer to Settings → Keys.

**Conversation digest**: the thread is the session. A header chip "Context: last N turns" shows what the digest currently carries (Sol gets ~1.5k tokens of recent user text + bot result summaries); **New conversation** (`⌘N`) resets the digest, not the history.

**Persistence/search**: `messages` in SQLite; thread loads the latest 100 and pages upward; `⌘F` searches text (SQLite FTS) across conversations with jump-to; per-message menu: copy, open trace, retry as new task, delete; Privacy tab clears everything.

**Quick entry**: same `Composer` in the `quick-entry` panel; on send the panel closes and the pill expands with the intake tag, then the result.

## 7. Assist · Queue

Header: count · **Pause queue** switch · paused-reason banner. `TaskCard` by task state:

| State | Card |
|---|---|
| `queued` | goal text, route tag, source glyph; drag to reorder, edit text, delete |
| `running` | expanded, `--working` pulse; current step sentence; `ProgressRing`; steps · elapsed · spend vs cap; **Stop**; read-only `question` and canvas tasks running concurrently (A10) show side by side with a "parallel" tag |
| `needs_confirm` | **confirm card** (below) |
| `waiting_user` | **ask card**: question, quick-reply chips, text box, "answering by voice works" hint, 30 s voice window indicator |
| `done` | collapsed summary, spend, duration, **Open trace**, **Do again** |
| `failed` | reason in plain words (`screen locked`, `interrupted`, `blocked: login wall`, `cap: $1.00 reached`, `denied by you`), **Retry**, Open trace |
| `cancelled` | one line, `--muted` |

**Paused reasons** (banner + status strip + pill, each with its fix): `screen locked` (auto-resumes) · `display asleep` · `you're using the Mac` (idle wait, countdown) · `paused by you` · `daily cap reached` (→ Safety) · `Jev unreachable` (risk fails closed; retry button) · `key missing/invalid` (→ Keys) · `Accessibility permission revoked` (→ onboarding re-entry) · `update installing`.

**Confirm card anatomy** (top→bottom):
1. **Why it stopped**: `rule` (which deny/must-confirm rule or pack policy) or `head` (which safety head crossed its threshold) or `spend`.
2. **Action sentence**, large: "Click **Post** on x.com".
3. **Context**: web → page title, origin, tab favicon, element role + label + nearby text; native → app, window, element. **Show me** raises the target (ring flashes, managed Chrome comes forward).
4. **Safety-head probability bars**: `outward` · `destructive` · `spends` · `on_task`, each a `ProbabilityBar` with its threshold tick; crossed bars in `--confirm`/`--danger`. Click → the exact state and heads sent to Jev.
5. **Cost estimate** (media and paid pack tools): "~$0.40 · 4 images · flux-dev", plus task and daily totals against their caps.
6. **Approve** (`⌘↩`) · **Deny** (`⌘⌫`) · checkbox **"always allow this here"** = remember (app bundle id or web origin) + element label. The checkbox is **absent** when the `spends` head or a spend rule fired, for media cost confirms, and for pack-policy must-confirms. Countdown: 2 min → deny. Resolvable from the card, the thread mirror, the pill, or voice ("yes" / "no", local control vocabulary).

## 8. Assist · Mind

A virtualised vertical `TraceTimeline` for one task — the running one by default, or whichever card is selected. Auto-follows the newest item unless the user scrolls up ("Jump to live" chip).

| Item | Shows |
|---|---|
| **Route** | intake result: intent + route distributions, chosen route, routine match and confidence if any, "zero Sol calls" badge for `navigate` |
| **Thought** | Sol's reasoning summary, italic, token-streamed |
| **Steer ticker** | navigator steps, one line each, ≤ 10 rendered/s: `CLICK [12] "Search" 0.97 · 164 ms`. Expand a line → the **operation** distribution, the top-5 **target** distribution with labels, the four safety heads, and the outcome (`executed` · `stale → re-observed` · `gated` · `blocked`). Grouped under the goal sentence (and under Sol's `navigate` call when Sol drives) |
| **Text helper** | field, the value written (masked for fields flagged sensitive), latency, `null` = "value unknown" |
| **Action** | Sol-level tool call: `why` sentence + action sentence; raw JSON behind a disclosure; duration |
| **Judgment** | `ProbabilityBar`s for a standalone Jev call (grounding, completion check, micro-edit); click → state + heads |
| **Saw** | collapsible observation or diff, the targeted element highlighted, `+`/`-`/`~` coloured |
| **Said / Asked** | TTS lines; `ask_user` exchanges with the answer and how it arrived |
| **Amended** | the user's amendment, threaded where it landed, with the rebuilt goal |
| **Gate** | rule or head, outcome: `denied` · `approved by you` · `remembered` · `timed out` |
| **Media** | media call: model, prompt excerpt, estimate → actual cost, resulting takes as thumbnails |
| **Canvas pass** | pass name (skeleton, content, imagery, refine…), op count, critique text, before/after look thumbnails; click → frame in Design |
| **Pack** | `loaded skill …` · `routine new_note (Jev 0.91)` · `pack tool …` |

**Past tasks**: selecting any card calls `get_trace(task_id, before_seq?, limit)` and pages from SQLite (compressed observations inflate in Rust); live items for the running task arrive by event/channel and append to the same list. The Mind pane is therefore also the history viewer and the debugger. Header: task picker, filter chips per item kind, "copy trace (redacted)".

**Managed-Chrome presence**: a `--working` chip in the Mind header, on the running card and in the pill: favicon · tab title · origin — "Stark's Chrome · holding this tab". States: `not running` · `idle` · `holding tab` · `needs sign-in` (navigator returned `BLOCKED: login wall`; button **Open to sign in**). **Show me** brings that Chrome window and tab forward; it never touches a tab the bot did not open (A4).

## 10. Identity

Settings → Identity (P8):

- **Name**: default "Stark", renamable (1–24 chars). Feeds the STT prompt/keywords, the name-required addressing mode, TTS self-reference, window/tray/pill titles, "Stark's Chrome".
- **`soul.md` editor**: plain Markdown at `~/Library/Application Support/com.starkbot.neo/soul.md`; in-app editor with preview, **Open in my editor** (file is watched), suggested sections *Who I am · How I speak · About my user · Standing preferences*. Saves apply from the **next task**; the editor says so.
- **Preferences-not-permissions notice**, pinned above the editor: "soul.md shapes style and workflow. It cannot change a safety rule, threshold, deny list or confirm — those live in Settings → Safety." Lines that read as permission changes ("never ask me to confirm") are underlined with "ignored — this is a safety setting".
- **History**: last 10 saves with diff and restore; **Reset to default**.
- Pack personas layer on top of the soul per task; the persona picker sits here and in the composer's `+` menu.

## 11. Onboarding

Full-window flow in `main`; each screen is a gate; Back always works; nothing listens until the privacy screen is accepted. Target: install → first task in < 3 min (M14).

| # | Screen | Content | Passes when |
|---|---|---|---|
| 1 | Welcome | what Stark is in three lines; what it may ask for (an inference connection, TypeSafe key, optional voice key, two permissions) | Continue |
| 2 | Intelligence | **Connect ChatGPT** (recommended when the user has an eligible plan) or **Use OpenAI API key**; plain comparison: plan allowance vs usage billing, beta badge on the Codex path, workspace-data-controls notice; both may be configured but one is the active runtime | Codex `account/read` says connected, or Rust validates and stores the API key; webview sees only redacted account state or `present` |
| 3 | TypeSafe key | `KeyField` (paste only, masked, never echoed back), "Get a key" link | one-head validation request succeeds |
| 4 | Voice | if an OpenAI API key is present: enable voice and **Allow** triggers microphone TCC, with a live waveform; ChatGPT-only users see "Voice needs an OpenAI API key" with **Add key** or **Start typed-only** — subscription auth is never reused for speech | microphone `granted`, or typed-only selected |
| 5 | Accessibility | why; deep link to System Settings; status polled every 1 s, flips green by itself; "Web-only for now" may continue with native tasks disabled | `AXIsProcessTrusted` true, or web-only selected |
| 6 | Listening & privacy | voice-enabled verbatim: *"Stark listens continuously while Listen is on. Only detected speech is sent to OpenAI for transcription. Nothing is recorded to disk. The orange dot in your menu bar is on whenever Stark is listening — and off whenever it says it is not."* Shows the toggle and `⌥Space`; typed-only says no microphone is opened | **Start listening**, **Start muted**, or **Continue typed-only** |
| 7 | First task | three suggestions typed/spoken/clicked (a Wikipedia lookup in Stark's Chrome, "what can you do?", open Settings); first use opens **Stark's Chrome** with a one-line "sign in to the accounts you want Stark to use" sheet | first task reaches `done` or the user skips |

**ChatGPT connection state**: the UI starts the official Codex helper's login flow and opens its returned URL in the system browser. It displays only connected email/workspace/plan when app-server reports them, rate-window usage/reset, **Reconnect**, and **Disconnect**. It never renders, receives or asks the user to paste a ChatGPT token. Reaching a plan limit pauses new Sol tasks and offers **Wait**, **Use API key** (explicitly billable), or **Choose another available model**; it never silently switches billing paths.

**Re-entry**: `PermissionChanged`, `KeyStatus` and Codex `account/updated` events drive it. A revoked microphone → bar `NO PERMISSION` + screen 4 as a sheet over the current mode; revoked Accessibility → native queue work paused with that reason + screen 5 as a sheet (web tasks in Stark's Chrome keep working); a missing active inference connection → screen 2 as a sheet and Sol work paused (Jev-only navigator work may continue); an invalid/missing TypeSafe key → screen 3 and navigator work paused. Sheets are dismissible; the affected capability stays paused until fixed. Doctor → **Run onboarding again** replays everything.

## 12. Settings

`⌘,` opens Settings inside `main`. Every change is `patch_settings` → validated in Rust → `SettingsChanged`. Locked rows (tightened by a pack policy) show a lock badge and the pack name.

| Tab | Setting → default |
|---|---|
| **Identity** | name → `Stark` · `soul.md` → seeded default · default persona → none |

## 13. Notifications, empty and error states

**Notifications** (`tauri-plugin-notification`) fire only when `main` is hidden or unfocused; clicking one shows `main` focused on the card. Kinds (default): confirm needed (on) · question asked (on) · task failed (on) · task done (on) · queue paused by a cap, Jev outage, or lost permission (on) · mic lost (on) · update ready (on). Approvals are **never** taken from a notification — only where the action sentence and context are visible (card, thread mirror, pill). Text never includes secrets or field values typed by the text helper.

| Surface | Empty state | Error state |
|---|---|---|
| Conversation | "Say something — or type." + three example asks | STT failure → greyed turn "couldn't transcribe" + Retry; inference auth/account → banner → Connections & Keys |
| Queue | "Nothing queued. Tasks appear here when Stark hears one." | paused-reason banner; worker crash → `failed: interrupted` cards on next start |
| Mind | "Pick a task to see how it went." | trace item that fails to decode renders as a raw-JSON item, never blanks the pane |
| Chrome presence | `not running` + **Open Stark's Chrome** | Chrome missing → Doctor link; `needs sign-in` |
| Design | **Enable media** card when the pack is off | doc 11 |
| Global | — | **Jev outage banner** ("confirming everything until Jev is back"), offline banner, bridge-version mismatch → "Restart to finish updating" |

## 14. Rust ↔ TS protocol

- **Types, commands and events are generated** with `tauri-specta` **2.0.0-rc** (exact pins of `tauri-specta` + `specta`, recorded in doc 05) into `ui/src/bridge/bindings.ts`, regenerated on every debug build and checked in CI (`git diff --exit-code`). Fallback if the rc bites: `ts-rs` for types + one hand-written `bridge/api.ts` with the same names.
- **Events** = low-rate state, fanned out to every window. **`Channel<T>`** = anything high-rate (Tauri's docs: events are not for throughput). Deltas are coalesced in Rust to ≤ 30 Hz before sending.
- **Bootstrap**: each entry calls `get_bootstrap()` once on mount → `{ bridge_version, settings, listen_state, conversation (latest 100 messages), tasks, queue_state, pending_confirms, pending_asks, browser_presence, health, spend, permissions, key_status, packs, models, onboarding_step? }`, then subscribes. Events carry a monotonically increasing `seq`; a gap → re-bootstrap.

## 15. Front-end architecture (DRY)

```
ui/
  main.html · pill.html · ring.html · quick-entry.html        Vite multi-page entries (+ fixtures.html, dev only)
  src/bridge/      bindings.ts (generated) · events.ts (one listener → store) · channels.ts
  src/store/       Zustand slices: listen · conversation · tasks · gates · trace · browser · health · spend · settings · packs · ui
  src/components/  shared by every entry and by both modes
  src/hooks/       shared
  src/assist/      ConversationPane · QueuePane · MindPane     src/design/   doc 11 (lazy chunk)
  src/settings/ · src/onboarding/ · src/fixtures/              src/styles/tokens.css  (the §2 tokens; the only place a colour literal exists)
```

- **State**: one Zustand store per window, fed by a single `useAppEvents()` subscription; reducers are pure functions `(state, AppEvent) → state` — the unit-test seam. Components select narrow slices; no component calls `listen()` or `invoke()` directly. Styling: CSS Modules over the token custom properties; no runtime CSS-in-JS.
- `ring` is **plain TS + one SVG, no React** (one instance per display — keep it tiny). `pill` and `quick-entry` are React and import the same components as `main`.
- **Components**: shell — `ListeningBar`, `Waveform` (canvas; bar + pill + onboarding), `StateDot`, `ListenToggle`, `KillSwitch`, `ModeToggle`, `StatusStrip` + `StatusSegment`, `Banner`, `Sheet`, `CommandPalette`; conversation — `ConversationThread`, `UserTurn`, `BotTurn`, `SourceGlyph`, `IntakeTag`, `QuickReplyChips`, `Composer` (main, strip, quick-entry), `AttachmentChip`, `DigestChip`; queue — `TaskCard`, `ProgressRing`, `ConfirmCard`, `AskCard`, `ConfirmMirror` (thread + pill), `PausedBanner`, `CostEstimate`; mind — `TraceTimeline`, one `*Item` per `TraceItem` kind, `SteerTicker` + `SteerLine`, `ProbabilityBar`, `DistributionList`, `DiffView`, `BrowserPresenceChip`; settings/onboarding — `SettingRow`, `ThresholdSlider`, `ModelPicker`, `KeyField`, `PermissionRow`, `ShortcutRecorder`, `SoulEditor`, `PackList`, `ConsentSummary`, `EnablementFlow`, `OnboardingStep`. Shared with Design: everything in shell + conversation, `ConfirmMirror`, `AskCard`, `SteerTicker`, `ProbabilityBar`, `CostEstimate`, `KeyField`, `EnablementFlow`.
- **Hooks**: `useAppEvents()` · `useBootstrap()` · `useListenState()` · `useMicLevel()` (channel → `ref`, never state) · `useChannel(open, onData)` (generic) · `useConversation()` · `useIntake(messageId)` · `useTasks()` · `useQueueState()` · `usePendingGates()` · `useTrace(taskId)` (paged + live) · `useSteerTicks(taskId)` · `useTextDeltas(taskId, kind)` · `useBrowserPresence()` · `useHealth()` · `useSpend()` · `useSettings()` / `useSetting(key)` · `usePacks()` · `usePermissions()` · `useCommand(fn)` (loading / error / fix-link wrapper) · `useShortcut(action, handler)` · `useReducedMotion()` · `useMode()`.

**Performance budgets**: waveform draws from a `ref` inside `requestAnimationFrame` — **zero React renders** from `mic_levels`; ≤ 2 ms/frame. Thread and trace virtualised (`@tanstack/react-virtual`): 10k messages / 5k trace items scroll at 60 fps. Channel and event bursts are batched into one store commit per animation frame; the Steer ticker renders ≤ 10 rows/s whatever arrives. Bar painted with real state ≤ 150 ms after window show; pane/mode switch ≤ 100 ms. JS budgets (gzip): `main` ≤ 350 KB without the lazy Design chunk · `pill` ≤ 90 KB · `quick-entry` ≤ 90 KB · `ring` ≤ 15 KB. Idle CPU with all panels up and Listen on: < 2 % of one core for the UI processes.

## 19. Risks

| Risk | Mitigation |
|---|---|
| `tauri-nspanel` has no crates.io release | revision `c9ec213…` is pinned and S6 proved pill/ring/quick-entry over fullscreen; vendor that revision if upstream goes stale; fallback = own the small objc2 `NSPanel` layer in `src-tauri` |
| `tauri-specta` rc churn | exact pins; `ts-rs` + hand-written `api.ts` fallback behind the same `bridge/` module |
| Runtime activation-policy transitions can order panels out | S6 reproduced the behavior: every transition reconciles policy and desired visibility together, then re-shows passive panels; signed-build release checks still watch for Dock icon flicker |
| Quick-entry key focus disturbs the automated app mid-task | while a desktop task is `running`, quick entry opens only between steps (Rust holds the next action until it closes, max 10 s) |
| Ring misplaced for web targets (page → screen mapping, zoom, multiple displays) | the observer owns the mapping and reports global points; ring is advisory — a wrong ring never affects where the action lands; Doctor self-test draws a calibration ring |
| Pill or `main` covering the target trips the click-occlusion guard | pill dodge; if `main` covers the target, Rust orders the managed Chrome window front without activating us |
| Transparent webviews cost GPU/battery | ring has no React and is empty at idle; pill waveform drops to 15 fps on battery; budgets in §15 measured on an Intel Mac |
| Event flood during a fast navigator run | channels + per-frame store commits + the ≤ 10 rows/s ticker; trace persistence is Rust-side and independent of the UI keeping up |
| The UI claims "not listening" while the mic is open (or the reverse) | `ListenState` is emitted only by `neo-voice` after the stream actually opened or dropped; the honesty check is a release gate |
