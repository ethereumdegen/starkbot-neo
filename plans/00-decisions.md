# 00 — Decision record (the constitution)

Every other doc must agree with this file. If a doc and this file disagree, this
file wins and the doc is wrong. Dated 2026-09-18. `U` = decided by the user,
`D` = decided in design (changeable, but not silently).

## Architecture

| # | Decision | By |
|---|---|---|
| A1 | **Rust only** behind the webview. **Never Python** — not for spikes, tests, scripts or tooling. JS/TS only where a browser engine requires it (the React UI, in-page `snapshot.js`). Edition 2024, rust-version 1.91. Everything below `src-tauri` is Tauri-free so the whole product runs headless in the **`neo` CLI**. | U |
| A2 | **Jev is a classifier (~100–180 ms/call) and is the fast inner loop**, not just a gate: many Jev calls, few LLM calls. | U |
| A3 | **Navigator = `jev-nav`**, a Rust port of `browser-use/jev-ultrafast` (read as reference, never executed). Whole goal in; per step **one TypeSafe request** with an `operation` head + one target head per operation over ≤ 250 observed controls, plus our safety heads; a fast text helper writes a value **only** on `TYPE_TEXT`. | U |
| A4 | **Web observation = CDP + one atomic in-page DOM/ARIA snapshot**, not the macOS AX tree. Default browser = a **neo-managed Chrome profile** ("Stark's Chrome": launched by the app with a debugging pipe, user signs in to their accounts once, sessions persist). Attaching to the user's everyday Chrome is an opt-in if Chrome's remote-debugging toggle proves workable *(verify in spike)*. The bot works only in tabs it opened. | D |
| A5 | **Native apps use the same navigator policy** through an `AxObserver` over `neo-ax` (objc2 AX bindings, one run-loop actor thread, batched attribute fetch). Safari/Firefox/Electron go this way too. | D |
| A6 | **One TypeSafe wire client** (raw `reqwest`, structured state, object criteria, `model` field) lives in `jev-nav::wire` and is used by every Jev caller. The `jev` crate is not a dependency (its `State`/criteria types are too narrow). | D |
| A7 | **Routing**: Jev intake classifies each utterance/message by *intent* (`new_task · amend · answer · question · cancel · chatter`) and new tasks by *route* (`navigate · design · media · multi · routine:<name>`). `navigate` goes straight to the navigator with **zero Sol calls**; `design`/`media`/`multi`/`question` start Sol. | D |
| A8 | **Sol = orchestrator + creative** behind `AgentRuntime`: either `metalcraft` (≥ 0.12) + `rig` on a direct OpenAI API key, or `CodexRuntime` on the official app-server with an eligible ChatGPT account. Both dispatch the same Starkbot tools through the same gates: multi-stage tasks as a sequence of `navigate(goal)` calls, `extract`, answering questions, writing long-form copy, art direction and visual critique, and recovery when the navigator returns `BLOCKED`. Fine-grained AX tools behind `Gated<T>` remain as Sol's manual fallback for native apps. | U (+D) |
| A9 | **Safety is layered and cheap**: deterministic rules (deny / must-confirm lists, secure fields, deny-listed apps/origins) → Jev safety heads in the *same* request as the decision (`outward`, `destructive`, `spends`, `on_task`) → human confirm card. Jev outages fail **closed** for risk. Screen/page text is data, never instructions. CAPTCHAs, bot checks, login walls, account creation → `BLOCKED`; the bot never tries to pass them. | D |
| A10 | One **queue**, one **desktop worker** (FIFO; one desktop = one actor). Read-only `question` tasks and **canvas work may run concurrently** with each other, never with a task that is acting on the desktop in the same app. | D |
| A11 | **Packs** = the Axoniac agent-pack format (data only: JSON + Markdown), shared with metalcraft-agent / starfire / degen-tools, plus a neo-only `desktop/` folder (native-app hints, **routines**, tighten-only policies). Built-in capabilities ship as embedded packs. Pack HTTP tools sit behind three fixed meta-tools so Sol's tool list never changes mid-task. Any pack with `requires_env` gets the same generic enablement flow. | U (+D) |
| A12 | *Superseded by A12′ (2026-09-19).* **Media engine = `degen-media-maker` as a library** (lib + bin split upstream), wrapped by `neo-media`; backends behind a `MediaBackend` trait (`fal`, `quiver`; `starkrouter` later); the pack ships **in every build, disabled**, enabled by a flow that collects the keys. Takes ledger + lineage kept. Quality pipeline: brief → per-model art direction → shoot-out → Sol vision critique against a rubric → targeted edits → finish → platform export presets. **All text in deliverables is set by our renderer, never trusted to an image model.** | U (+D) |
| A13 | *Superseded by A13′ (2026-09-19): retired with the Hypercanvas.* **Hypercanvas document model: every frame is HTML + CSS** (stable `data-n` node ids, CSS custom properties for every token and knob) — web pages, graphics, ad sets, slides and video scenes alike. Rust owns the document (parse → node tree, ops + transactions, per-author undo, tokens, storage); the agent changes frames by **rewriting subtrees** (generative) or by **ops** (micro-edits, knobs, user manipulation). Raster/PDF/video export render through a browser engine (CDP; `WKWebView` snapshot as fallback). `resvg` stays for pure-SVG assets. OpenPencil/Penpot are references, not dependencies. | D (from U's Claude-Design steer) |
| A14 | *Retired with A13′ (2026-09-19).* Canvas refinement UX: **pins** (element-anchored comments → scoped agent tasks), **knobs** (agent-generated sliders bound to CSS variables; dragging costs no model call), direct text edit, and **Jev micro-edits** by voice (`target` + `operation` + `amount` heads over a closed op vocabulary snapped to the token scale; anything generative → `NEEDS_SOL`). | U (+D) |
| A15 | UI: React + TS + Vite in the webview, DRY components + hooks, types generated from Rust. Two modes of the main window — **Assist** (Conversation · Queue · Mind) and **Design** (Hypercanvas) — sharing the always-present listening bar. Overlay mechanics live only in `src-tauri::panels` behind one main-thread `PanelController`, using `tauri-nspanel` pinned to revision `c9ec2130422200f0863b23dfdad02b133a529b07`: `pill` and click-through `ring` are never-key NSPanels under `Prohibited`; `quick-entry` is a separate key-capable NSPanel under `Accessory`; `main` / `design` use `Regular`. Every activation-policy transition reapplies intended panel visibility. | U (+D, proven S6) |
| A16 | Storage: SQLite (`rusqlite`, WAL) for app state; *(2026-09-19: studios now belong to Degen Media Studio, A13′.)* a **studio** is a plain folder (`studio.json`, `takes.jsonl`, `takes/`, `canvas/`, `exports/`) readable by the `dmm` CLI. | D |
| A17 | **Extensions use Omarchy-class ergonomics without Omarchy's trust model.** Packs remain portable, declarative data. An optional code tier is a signed or exact-hash-pinned `wasm32-wasip2` component run by a separate `neo-extension-host`: no ambient filesystem, network, environment, subprocess, Keychain or macOS APIs; every host capability is declared, consented and revocable, and every proposed desktop/browser/spend action re-enters `Gated<T>`. Namespaced ids, built-in/user discovery, enable/disable, clone-and-edit, hot reload in developer mode, update diffs, rollback and a community catalog match Omarchy's workflow. Native dylibs and unsandboxed in-process plugins are never loaded. | U (+D) |
| A18 | **Users may connect an eligible ChatGPT plan for Sol inference through OpenAI's official Codex app-server.** Neo ships a pinned, signed Codex helper and drives its documented stdio JSON-RPC auth/thread surface; Codex owns browser OAuth, refresh and Keychain credentials. Starkbot tools enter as client-executed dynamic tools and still pass `Gated<T>`. No token copying, private endpoint calls or silent fallback to billable API usage. ChatGPT access does not cover Jev, speech, fal or Quiver; direct keys remain supported. | U (+D) |

### Amendments 2026-09-19e (the heartbeat — user)

| # | Decision | By |
|---|---|---|
| P13 | **Starkbot runs a heartbeat: a user-authored `heartbeat.md` it acts on, on a timer, by default every hour.** The file lives in the config home (`~/Library/Application Support/com.starkbot.neo/heartbeat.md`), is plain Markdown written by the user, and is the only place standing work is declared: `using octaweave cli, read the active tasks on the xyz kanban board and do them`. Each tick is an ordinary Starkbot **task** — same queue, same routes, same caps, same trace — whose goal is the file's content, so a tick is indistinguishable from the user having typed the same sentence. Cadence, enablement and per-tick caps are settings (`heartbeat.*`, `every` default `1h`, minimum `5m`). An empty or missing file is not an error: the tick is skipped and recorded as skipped. | U |
| A26 | **The heartbeat may call user-declared CLIs, and that is the only command execution in Starkbot** (narrows P3 rather than reversing it). P3 stands: there is no `bash` tool, no shell, no pipeline, no model-chosen binary, and no general file access. What exists is a **settings-declared allowlist** (`tools.cli[]`): the user names each program by absolute path, gives it a Starkbot-visible name and a fixed leading argv, declares whether it mutates, and optionally pins a working directory. The model may only choose **which declared entry** to call and the **trailing arguments**, which are passed as an argv vector to that exact program — never through a shell, so quoting, `;`, `&&`, `$(…)`, redirection and globbing have no meaning. A mutating entry is gated exactly like any other outward action (P5/A8); a heartbeat tick that hits a gate **holds the task and waits** rather than auto-approving, because a timer is not consent. Output is captured, truncated to a byte cap, and recorded in the trace. | U |
| A27 | **The heartbeat never overlaps itself and never catches up.** One tick at a time per install: if a tick is still running when the next is due, the due tick is dropped and the drop is recorded (a stuck hour must not queue twelve copies). Missed ticks — the machine was asleep, Starkbot was closed — are not replayed; the next tick simply runs on the next boundary. Consecutive failures back off (2×, capped at 6 h) and the Doctor reports the heartbeat row: enabled, cadence, last tick, outcome, next due. | U |


### Amendments 2026-09-19f (the chat surface, voice in, and the Keychain — user)

| # | Decision | By |
|---|---|---|
| P14 | **The front end is a chat with an agent, not a settings screen.** `neo tui` opens on the Conversation panes; it only opens on Connections when setup is genuinely incomplete (no TypeSafe key, or no usable inference connection), and the header names every reachable screen (`Esc chat · , settings · ? keys`) so no surface is invisible. Typing a message runs one **agent turn**: the model picks one action per step — `browse`, `app`, `answer`, `ask` — the core executes it through the same `jev-nav` policy as `neo nav`, and the thread records the result. `DEFAULT_MAX_STEPS = 8`; an exhausted turn says so rather than stopping silently. A turn runs as a background task, so the UI keeps drawing, the kill switch keeps working and each navigator step appears as it happens. | U |
| K8 | **On-device dictation is a first-class speech-to-text backend (amends K6's "speech is OpenAI-API-key only").** K6 would have left a user with no OpenAI key unable to speak to Starkbot at all. `neo-voice` defines one `Transcriber` trait with two implementations: macOS `SFSpeechRecognizer` with `requiresOnDeviceRecognition = true` — **no key, no cost, no audio leaving the machine** — and OpenAI `gpt-transcribe`, used when a key exists. **Speech *out* (TTS) stays OpenAI-key-only**, so the Doctor has two rows: `dictation` (voice in) and `speech out`. Capture is push-to-talk (`v`, or `Ctrl-V` while typing), 16 kHz mono, capped at 120 s; a transcript lands **in the composer**, never sent automatically — a misheard sentence must not become an action. | U |
| A28 | **Three OS grants gate voice, each reported separately with its own fix.** Microphone (TCC), Speech Recognition (TCC), and the **Siri & Dictation** switch in System Settings. All three are read-only probes: Starkbot **never writes a system setting** on the user's behalf. Each failure names the one thing to change and deep-links to the right pane. Both TCC grants attach to the *responsible* process, exactly as the Accessibility grant does ([01](01-accessibility.md)), so `neo tui` must be launched from a real terminal. Gotcha recorded in [02](02-voice.md): `SFSpeechRecognizer` dispatches its result handler on the **main** operation queue by default, so off the main thread it never fires — give the recogniser its own `NSOperationQueue`. | U (+D) |
| A30 | **A debug build never touches the login Keychain.** Signing and re-sealing (A29) reduce the prompts a *signed* binary raises, but they cannot fix `cargo test`: a test binary is unsigned, its identity changes on every build, and every credential read raises a **modal** authorization dialog — so a single `cargo test --workspace` asked for the login password once per item per run, and a modal dialog behind an agent turn looked like a hang. So storage is a backend choice in `neo-keys`: the login Keychain (`SecItem*`) or a **file**, owner-only (0600), written atomically by write-then-rename. **Debug builds default to the file; release builds default to the login Keychain**, and either can be overridden with `NEO_KEYCHAIN_BACKEND=login|file` or `NEO_KEYCHAIN_FILE=<path>`. The path is chosen by each `Runtime` as `<data_dir>/keys.json`, never one global path — a single shared path *was* the first attempt, and parallel tests corrupted it with concurrent read-modify-write. `neo keys import-login` copies what the signed app stored into the dev file, one prompt per item, once. Dev-loop reads went from 4.7 s with a dialog to **0.00 s, silent**. The file holds secrets in clear text, which is precisely why a release build does not use it. | U (+D) |
| A29 | **Dev builds are code-signed, and stored credentials are re-sealed to that identity.** A Keychain item's ACL and a TCC grant are both keyed to the *code-signing requirement* of the process asking. An unsigned or ad-hoc build has no stable identity — its hash changes on every `cargo build` — so the user is re-prompted for **every credential on every launch**, and because the dialog is modal an agent turn appears to hang. Three things follow: `scripts/sign-dev.sh` signs with a real identity and a fixed `--identifier`; `neo keys reseal` (`Runtime::reseal_credentials`) rewrites every stored item so its ACL belongs to the current identity; and `Runtime` caches each secret and OAuth credential **for the process lifetime**, invalidated on every write. Measured: **4.7 s and a dialog per read** before, **0.04 s and silent** after. | U (+D) |


### Amendments 2026-09-19g (app-control evals on spice-framework — user)

| # | Decision | By |
|---|---|---|
| S9 | **App control is measured by an agent-in-the-loop eval suite, not by unit tests.** `neo-eval` + `neo eval` run the real agent loop against real applications on `spice-framework` (the user's own crate, `~/ai/spice`, **unchanged** — `AgentUnderTest`, `Judge` and `Assertion::Custom` were all the seams needed). Each case runs **5 times and must pass 4**, which is the S8a bar, because a UI-driving agent that passes once is not working and one that fails once is not broken. Cases run **one at a time**: they share the keyboard, the frontmost application and the screen. An eval costs plan quota and cannot run in CI, so it is its own command and never part of `cargo test`. | U |
| S10 | **Every case asserts the application's state, never the model's prose.** After the turn, a **probe** re-reads the surface through the same accessibility/CDP path the agent used and is attached as a synthetic `probe` tool call *whose arguments are the observed state*, so ordinary assertions (`ExpectToolArg("probe", "value", …)`) are statements about the document. A run where the model claims success and the cell is empty fails. The cell probe reports `present`, `value` and `found` separately: "not in the table", "there and empty" and "there with a value" are different failures. | U |
| S11 | **Every case that drives a document app declares a fixture**, applied before the agent sees the app, and a fixture failure is reported as a *harness* error rather than scored as a model failure. This is not hypothetical: the first TextEdit run was graded against a document a previous session had left open, and the first LibreOffice runs failed because a running LibreOffice with **no open document has no focused window**, so there is nothing to resolve a menu against. Fixtures therefore open a real document — for Calc a generated **flat ODF** (`.fods`) file, because a `.csv` raises the Text Import dialog and a fixture must never leave a modal in front of the agent. | U (+D) |
| A31 | **An observation carries what the surface said, not just that it was visited.** Found by S9 on its first run: asked for a fact from a page, the agent *browsed and then asked the user what it had read*, because the observation was `Done · ended at <url>` with no content. `browse` and `app` now append up to 2,000 characters of the page's or window's text to the observation. The eval case went from fail to pass on the same prompt, which is the evidence. | U (+D) |


### Amendments 2026-09-19h (several Starkbots on one laptop — user)

| # | Decision | By |
|---|---|---|
| A32 | **Every Starkbot process on a machine joins one roster, and the things there is only one of are leased.** Several processes share a data directory — a TUI, the desktop app, a `neo eval` run, a one-off `neo app …` — and they share **the keyboard and the frontmost application** (every `neo-ax` action is a global CGEvent or an `AXPress` on whatever is in front) and **the managed Chrome profile**. Two agents driving TextEdit at once do not produce two documents; they produce one document with both their keystrokes interleaved. So `neo-store` gains `sessions` (id, kind, pid, host, activity, heartbeat) and `leases` (resource, holder, reason, expiry) at schema v5, and `Runtime` gains `announce`/`heartbeat`/`sessions`/`depart` plus `hold(Resource, reason)` returning an RAII guard. `Resource` is coarse on purpose — `keyboard`, `chrome`, `app:<name>` — because a finer claim would let two processes each believe they had exclusive use of one window. | U |
| A33 | **The store is the coordination point; there is no broker.** It is already the shared, WAL-backed, multi-process-safe thing every process opens, and a lease is one `INSERT … ON CONFLICT … WHERE holder = excluded.holder OR expires_at < now`, which SQLite makes atomic across processes: two racing processes produce one winner and one `changes() == 0`. A daemon would add a moving part and a new failure mode for the same guarantee. Leases **expire** (30 s) and are renewed by the same heartbeat that reports activity, so a crashed holder cannot block the laptop; a clean exit drops the session row and cascades its leases so the next process does not wait out an expiry. | U (+D) |
| A34 | **Losing a lease is a named answer, never a wait or a silent overwrite.** `RuntimeError::Busy { resource, who, doing }` renders as *"the keyboard is in use by the command (pid 70565), which is driving TextEdit"* — it names the holder's kind, pid and current activity, taken from the roster. `neo sessions` prints the roster, `neo doctor` carries a `sessions` row, and the TUI heartbeats a one-line activity (`idle`, `running a turn`, `dictating`, `in settings`) that another session's user can read. The activity line is plain words by contract: **never a prompt and never a credential**, because it is written for somebody else's screen. | U |


### Amendments 2026-09-19i (one page at a time; one exclusion mechanism — user)

| # | Decision | By |
|---|---|---|
| P15 | **The TUI shows one page at a time, full width, the way the OMP harness does** (supersedes the three-column layout of 14 §2). Three side-by-side panes were wrong for this front end: the Conversation is the surface a user *reads*, and on an 80-column terminal a third of the width re-wraps a sentence every four words while two columns sit mostly empty. The Conversation page has **no border** — the whole terminal width goes to the text — and the reference pages (Runs, Mind/Activity) keep a titled frame because their titles carry counts. Pages are reached by number (`1`/`2`/`3`), `Tab`, or `<`/`>`, which now move between pages instead of resizing splits; the page strip names both the page and its key, because a tab bar that does not say how to reach a page is decoration. Settings stays a separate view on `,`. | U |
| A35 | **One mechanism for excluding concurrent runs, one for seeing them.** Two were built in parallel: an `flock` on `<data_dir>/screen.lock` (`neo-agent::screen::ScreenLease`) and a SQLite `leases` table with a 30 s TTL (A32/A33). **The `flock` wins for exclusion**, on one decisive property — the kernel releases it when the holder dies, however it died, so there is no stale window at all, where a TTL lease blocks the next process for up to its expiry. The **roster stays** (`sessions`, `neo sessions`, the Doctor row, the TUI's heartbeat activity): `flock` can only say *somebody* holds the screen, and the roster is what turns that into *"the terminal (pid 70479), which is running a turn"*. So whoever wires `ScreenLease` into `agent/tools.rs` deletes `Runtime::{lease, unlease, hold}` and the `leases` table with it, and reads the holder's identity from `sessions` for the message. Until it is wired, the TTL lease is the only live guard and stays in place — removing it first would leave a window with nothing guarding the keyboard. | U (+D) |
